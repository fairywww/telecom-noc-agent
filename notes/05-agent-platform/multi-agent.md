# 多 Agent 协作：总控与专家子 Agent

**范围说明**：本文基于 `noc_agent/agent/orchestrator.py`、三份人设提示词（`prompts/orchestrator.txt`、`data_analyst.txt`、`knowledge_expert.txt`）与 `noc_agent/agent/loop.py` 的参数化改造。核心问题：**什么时候值得把一个 Agent 拆成多个，代价是什么。**

## 1. 架构：Agent as Tool

```
            总控 Agent（编排，不直接查数据）
             |                     |
      consult_data_analyst        consult_knowledge_expert     ← 对总控而言只是两个工具
             |                     |
      数据分析子 Agent        知识规范子 Agent    ← 各自是完整的 Agent 循环
      （三个指标工具）         （search_ops_knowledge）
```

子 Agent 被包装成普通函数注册进总控的 TOOL_REGISTRY（工具表）——总控"调用专家"与"调用接口"在机制上没有任何区别。这一模式称为 Agent as Tool，是多 Agent 系统最简单也最常用的组织方式。

## 2. 实现：没有新机制

全部改动是给 `run_agent_stream()` 增加两个参数：`toolset`（工具子集或自定义工具）与 `system_prompt`（人设）。子 Agent = 装上专属人设与受限工具箱的同一个循环；`build_expert()` 再把它包成一个带 `task` 参数的工具。

三个设计点：

1. **工具边界即职责边界**：数据专家拿不到知识库工具，知识专家拿不到指标工具——分工不是靠提示词恳求，而是靠能力上的硬隔离；
2. **人设互补**：数据专家被要求"不提供制度建议"，知识专家被要求"不回答数据问题"，总控被要求"自己不查数据、标注来源、指出矛盾"；
3. **子任务自包含**：总控提示词要求分派的子任务"自包含、无歧义"——子 Agent 看不到原始对话，任务描述是它唯一的上下文。

## 3. 实测行为

任务："南京退服全网最多，情况有多严重？按规范接下来该怎么处置？"

- 总控把任务拆成两个高质量子任务分派（给数据专家的子任务甚至主动包含了"近 24 小时趋势"这一维度）；
- 数据专家如实回报"趋势数据当前接口无法提供"，该局限被总控**原样传递**到最终答复，未被掩盖；
- 最终答复逐段标注信息来源（数据分析专家 / 知识规范专家），并按提示词规则确认"两位专家结论无矛盾"。

## 4. 成本：拆分不是免费的

同一问题分别用单 Agent（全部工具）与多 Agent 运行的实测对比：

| | 单 Agent | 多 Agent |
|--|---------|---------|
| 词元 | 3 215 | 8 509（总控 3 735 + 专家 4 774） |
| 耗时 | 18 秒 | 52 秒 |
| 答案质量 | 完整正确 | 结构更细、带来源标注 |

**约 2.6 倍词元、2.9 倍耗时**。原因：每个子 Agent 都有自己的系统提示与完整对话历史，且总控要把子任务与结论各传输一遍。

### 何时值得拆

- 工具数量多到单一 Agent 的说明书互相干扰、选错工具率上升；
- 职责需要**硬隔离**（权限、数据范围各不相同——运维场景常见）；
- 子领域需要深度人设（提示词长而互斥，塞进一个 system prompt 互相稀释）。

### 何时不该拆

- 本项目这种 4 个工具的规模，单 Agent 完全胜任——本次拆分是教学目的；
- 对延迟敏感或成本敏感的高频简单任务。

**先把单 Agent 做到上限，再考虑拆分**——与"文档少时不上向量库"（[../03-rag/rag-basics.md](../03-rag/rag-basics.md) 第 2 节）是同一judgment。

## 5. 当前局限

- 子 Agent 的工具调用轨迹不会透传到总控的事件流（SSE 前端只能看到"咨询了专家"，看不到专家内部动作）；
- 两位专家串行咨询，无并行；
- 总控转述专家结论时存在失真风险，重要数字宜以专家原文为准。

## 6. 验证

```bash
python3 -m noc_agent.agent.orchestrator "南京情况多严重？按规范怎么处置？"
```

预期：先后出现两条"咨询专家"工具事件，最终答复分段标注来源。
