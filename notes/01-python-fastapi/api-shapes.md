# 聚合接口与明细接口

**范围说明**：本文基于 v0.2 中"地市退服分布"面板的接入过程，涉及 `adapter.py` 的 `/api/city-outage` 接口与 `index.html` 的条形图渲染。核心问题：**同一份原始数据，为什么要设计成两种形态的接口，以及数组契约如何设计才耐演进。**

## 1. 两种接口形态

本项目适配层现有两个接口，消费同一份 NOC 原始数据，形态不同：

| 接口 | 形态 | 返回结构 | 前端用途 |
|------|------|---------|---------|
| `/api/kpi` | 聚合型 | 若干标量字段（`outage_total` 等） | KPI 数字格 |
| `/api/city-outage` | 明细型 | 对象数组（`cities` 列表） | 条形图、表格、排名 |

划分依据是前端的展示需要：数字格只要一个数，图表要一行一条记录。**不要用一个"大而全"的接口同时服务两种场景**——那会使每个使用方都拿到多余数据，且任何一方的需求变化都牵动所有使用方。

## 2. 明细接口的实现

`adapter.py` 中 `/api/city-outage` 的构造过程（列表推导式 + 字典推导式）：

```python
城市列表 = [
    {
        "city": 地市,
        "by_tech": {专业: 数据["outage_count"] for 专业, 数据 in 各专业.items()},
        "total": sum(数据["outage_count"] for 数据 in 各专业.values()),
    }
    for 地市, 各专业 in 行.items()
]
城市列表.sort(key=lambda 城: 城["total"], reverse=True)
```

等价的普通循环写法：

```python
城市列表 = []
for 地市, 各专业 in 行.items():
    by_tech = {}
    for 专业, 数据 in 各专业.items():
        by_tech[专业] = 数据["outage_count"]
    城市列表.append({"city": 地市, "by_tech": by_tech, "total": sum(by_tech.values())})
```

推导式是"从旧集合映射出新集合"这一模式的紧凑写法；嵌套超过两层时应退回普通循环以保持可读。

### 排序放在服务端的理由

排序口径（按退服总数降序）属于业务语义，不是显示细节。放在服务端，所有使用方（大屏、将来的移动端、报表）看到同一顺序；放在前端，则每个使用方各排各的，口径漂移。一般规则：**多方共享的口径放服务端，单方特有的显示逻辑放前端。**

## 3. 数组契约的演进性设计

数组元素的结构同样是前后端契约。本接口的元素为：

```json
{ "city": "南京", "by_tech": { "4G": 40, "5G": 24 }, "total": 64 }
```

设计要点：各专业数字放在 `by_tech` 字典中，而不是写成 `outage_4g`、`outage_5g` 两个固定字段。两种方案的差异在数据源新增专业（例如 700M）时显现：

| 方案 | 数据源新增专业时 |
|------|----------------|
| `by_tech` 字典 | 适配层与契约零改动，前端多渲染一段 |
| 固定字段 | 契约要加字段、适配层要改代码、前端要加取值 |

原则：**枚举会增长的维度（专业、厂家、地市），用字典或数组承载；确定不变的维度才升格为字段名。**

## 4. 前端：明细列表 → 条形图

`index.html` 的渲染逻辑（`取地市退服并展示()` 函数）分三步：

1. **归一化**：取全部城市 `total` 的最大值作为宽度基准，每段宽度 = `值 / 最大 × 100%`，保证各行条长可比较；
2. **分段**：遍历 `by_tech` 的键值对生成分段 `<div>`，段色按专业区分，鼠标悬停时 `title` 属性显示明细数值；
3. **拼装**：模板字符串生成整块 HTML，一次性赋给 `innerHTML`（比逐元素 DOM 操作简单，数据量小时性能足够）。

条形图未引入图表库：三行数据用 CSS 就能表达，引库的成本（体积、学习、升级）在此不划算。数据量或图形复杂度上去之后再考虑 ECharts 一类的库。

## 5. 分层验证

| 步骤 | 验证点 | 预期 |
|------|--------|------|
| 1 | `http://localhost:8002/api/city-outage` | `cities` 数组按 total 降序：南京 64、苏州 58、无锡 31 |
| 2 | `http://localhost:8002/` 页面中栏 | 三行条形，长度比例约 64 : 58 : 31，图例区分 4G/5G |
| 3 | 悬停任一色段 | 提示"地市 专业：数值" |
