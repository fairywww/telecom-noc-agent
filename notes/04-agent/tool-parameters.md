# 带参数的工具与 Agent 服务化

**范围说明**：本文基于 v0.5 的改动：`agent.py` 新增带参数工具与防御式执行，`adapter.py` 新增 `/api/city-detail` 与 `/api/agent` 接口，`index.html` 新增诊断对话面板。前置阅读：[agent-loop.md](agent-loop.md)。

## 1. 带参数的工具

无参数工具的 schema 是空对象；带参数工具需要完整描述每个参数：

```python
"参数": {
    "type": "object",
    "properties": {
        "city": {"type": "string", "description": "地市名，例如 南京、苏州、无锡"},
    },
    "required": ["city"],
}
```

两个要点：

1. 模型返回的 `arguments` 是 **JSON 文本**（如 `'{"city": "苏州"}'`），执行前必须 `json.loads` 解析，随后 `函数(**参数)` 展开传参；
2. 参数的 `description` 要给出**取值示例**——模型完全靠它猜测合法取值。实测提问"苏州的情况"，模型准确产出 `{"city": "苏州"}`。

## 2. 防御式执行：错误回填而非抛异常

模型产出的调用请求是文本，可能出各种错：参数不是合法 JSON、工具名不存在、参数与函数签名不匹配、工具本身执行失败。`agent.py` 的 `执行工具()` 把四类失败统一转成 `{"error": ...}` 回填给模型：

| 失败类型 | 捕获方式 |
|---------|---------|
| 参数非法 JSON | `json.JSONDecodeError` |
| 未知工具 | `名 not in 工具表` |
| 参数不匹配 | `TypeError` |
| 网络/接口失败 | `requests.RequestException` |

原则：**Agent 循环里，错误是数据，不是事故**——回填错误信息，模型看到后会换工具、改参数或向用户说明；抛异常则整轮对话报废。

另一处防御：个别服务偶发返回空 `choices` 的 200 应答，循环开头显式检查并携带原始应答报错，避免 `NoneType` 这类掩盖真相的错误。

## 3. 服务端参数校验的三道防线

`/api/city-detail` 展示了三层校验各管一段：

| 防线 | 机制 | 出错表现 |
|------|------|---------|
| 框架层（查询参数） | `def city_detail(city: str)` 必填声明 | 缺参数时 FastAPI 自动 422 |
| 框架层（请求体） | Pydantic 模型 `class 提问(BaseModel)` | 字段缺失/类型错自动 422 |
| 业务层 | 未知地市返回 `{"error": ..., "可选地市": [...]}` | 200 + 错误说明 |

业务层错误特意不用 4xx：把"可选地市"一并返回，Agent 看到后能**自行纠正**重新调用——这与第 2 节的"错误是数据"是同一设计思想。

## 4. Agent 服务化

`POST /api/agent`（请求体 `{"question": ...}`）把 `运行Agent()` 包成 HTTP 接口，返回：

```json
{ "answer": "诊断结论…", "trace": [{"工具": "...", "参数": "...", "摘要": "..."}], "rounds": 3 }
```

- `trace` 是执行轨迹，前端逐条展示"Agent 调了什么、拿到什么"——**可解释性是运维场景采信 AI 结论的前提**；
- Agent 依赖（LLM 配置）通过**延迟导入**引入，不用诊断功能时大屏后端照常启动；
- 演示项目将其挂在大屏后端进程内；生产中应拆为独立服务——Agent 请求耗时长达数十秒，与毫秒级数据接口的资源特性完全不同。

## 5. 实测行为：串行依赖的多轮取数

v0.4 的运行是"一轮并行调两个工具"；本次提问"苏州需要重点关注吗"出现了新模式：

```
第 1 轮：查指定地市明细(city=苏州) → 拿到苏州数据
第 2 轮：查全网概览() → 模型意识到"没有全网基线无法判断轻重"，补查
第 3 轮：给出结论（苏州占全网退服 37.9%、告警 34.8%）
```

第 2 轮的补查没有任何代码或提示词要求——模型根据第 1 轮结果**自主决定**还缺什么。并行（无依赖）与串行（有依赖）两种取数模式，模型都能自行选择，这正是把控制流交给模型的价值。

## 6. 验证

| 步骤 | 验证点 | 预期 |
|------|--------|------|
| 1 | `GET /api/city-detail?city=苏州` | 苏州分专业明细与两项合计 |
| 2 | `GET /api/city-detail?city=常州` | error + 可选地市列表 |
| 3 | `GET /api/city-detail`（缺参数） | 422 |
| 4 | `POST /api/agent` | answer + trace + rounds |
| 5 | 大屏右栏提问 | 轨迹逐条显示，随后出结论 |

注意：中文查询参数在 curl 里需 URL 编码（`curl -G --data-urlencode "city=苏州"`），浏览器与 requests 会自动处理。
