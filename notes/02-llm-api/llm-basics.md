# 大模型 API 调用基础

**范围说明**：本文基于 `llm.py`、`prompts/system.txt` 与 `.env` 的实现过程。核心内容：OpenAI 兼容格式、密钥管理、流式输出与推理模型、System Prompt 的实际作用。

## 1. OpenAI 兼容格式

OpenAI 的聊天接口格式已成为行业事实标准。国内外主流服务均提供兼容端点，切换供应商只需改配置，代码零改动：

| 供应商 | base_url | 说明 |
|--------|----------|------|
| ModelScope | `https://api-inference.modelscope.cn/v1` | 本项目当前使用，有每日免费额度 |
| 阿里 DashScope | `https://dashscope.aliyuncs.com/compatible-mode/v1` | Qwen 官方商用 |
| DeepSeek 官方 | `https://api.deepseek.com/v1` | |
| 本地 Ollama | `http://localhost:11434/v1` | 完全离线，适合内网环境 |

一次调用的三要素（`llm.py` 第 33–38 行）：`base_url`（找谁）、`api_key`（凭什么）、`model`（用哪个模型）。

### messages 结构

请求体的核心是 `messages` 数组，每条消息一个角色：

| 角色 | 用途 | 本项目对应 |
|------|------|-----------|
| `system` | 设定身份与行为规则，优先级最高 | `prompts/system.txt` |
| `user` | 用户输入 | 命令行传入的问题 |
| `assistant` | 模型此前的回答（多轮对话时由调用方带上） | 暂未使用 |

**接口是无状态的**：服务端不记忆任何历史，多轮对话需要调用方把之前的 user/assistant 消息全部重发。这一点是后续 Agent 循环的基础——所谓循环，就是不断向 `messages` 追加消息再重发。

## 2. 密钥管理三件套

密钥绝不进代码库（公开仓库人人可见；即使删除，git 历史仍可翻出，清洗成本高）。本项目的做法：

| 文件 | 是否提交 | 作用 |
|------|---------|------|
| `.env` | 否（已进 `.gitignore`） | 真实密钥与本地配置 |
| `.env.example` | 是 | 模板，告诉协作者需要配置哪些项 |
| `llm.py` 中的 `加载环境文件()` | 是 | 启动时把 `.env` 内容写入环境变量 |

代码中通过 `os.environ["LLM_API_KEY"]` 读取——用方括号而非 `.get()`，缺失时立即报错，避免带着空密钥继续运行到更难排查的位置。

## 3. 请求参数

- `temperature=0.2`：控制随机性（0–2）。运维问答要求稳定、可复现，取低值；创意写作类任务才取高值。
- `max_tokens`：答案长度上限，本项目暂未限制。
- `stream=True`：见下节。

## 4. 流式输出与推理模型

`stream=True` 时，应答不再是一次性返回的完整对象，而是一串**块（chunk）**：每块的 `choices[0].delta` 只含新增的几个字。底层传输协议是 SSE（Server-Sent Events），HTTP 连接保持打开、服务端持续推送。流式的价值：答案生成需要数十秒时，用户第一秒就能看到开头，而不是面对空白等待。

推理模型（DeepSeek-V4、Qwen3.5 等）的 delta 中有两个字段：

| 字段 | 内容 |
|------|------|
| `reasoning_content` | 思考过程，先到 |
| `content` | 最终答案，后到 |

`llm.py` 的处理：思考过程仅在流式打印时展示，函数返回值只含最终答案——调用方（将来的 Agent）只需要结论。

## 5. System Prompt 的实际作用

`prompts/system.txt` 设定了三条规则：结论先行、数字判断给依据、缺信息时明说。实测提问"苏州需要重点关注吗"，回答呈现：

1. 第一行即结论（"需要重点关注"）；
2. 给出计算依据（苏州占全网退服 37.9%）；
3. 单列"缺失的关键信息"（基站基数占比、历史基线、告警级别分布）。

三条规则全部生效。提示词放在 `prompts/` 目录单独管理而不是写死在代码里，便于不改代码迭代措辞、对比效果。

## 6. 工程经验：模型可用性排查

接入过程中遇到的三类错误及含义：

| 现象 | 含义 | 处置 |
|------|------|------|
| `429 insufficient_quota` | 认证通过，但账号无该模型的额度 | 换免费额度内的模型，或充值 |
| `400 no provider supported` | 模型在目录中但当前无算力供应 | 换模型 |
| `401` | 密钥无效 | 检查密钥 |

排查工具：`GET {base_url}/models` 列出目录；目录仅代表"登记过"，**可用性要以真实调用为准**——用一个 `max_tokens=16` 的最小请求逐个探测候选模型，第一个成功的即可用。
